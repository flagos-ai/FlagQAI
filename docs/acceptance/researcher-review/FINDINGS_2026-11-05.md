# Five-domain internal workflow findings — 2026-11-05

The current workbench has a concrete strength in **circuit experiment iteration,
artifact provenance and replay**. This review does not establish a complete
cross-domain quantum research environment, user demand or product-market fit.
Four scientific checks passed; no scenario completed the entire designed research
workflow inside the current UI. Chemistry was environment-blocked. All evidence
comes from one internally operated, developer-assisted walkthrough.

central conclusion cannot yet be inspected, compared and recovered as a complete
research deliverable using the tested UI path.

## What contributed real value

- The SDK and worker produced real circuits and results. The Web automatically
  collected 14 .fqx files and linked them to immutable run/source snapshots.
- Jobs exposed sampled QAOA distribution changes and operation differences.
  It correctly warned that distribution distance is not fidelity or causal proof.
- Fourteen exported files survived independent-process loading and execution;
  exact states and seeded sample counts matched their saved evidence.
- Refresh preserved unsent chat and unsaved editor sentinels, the existing failed
  run and five submitted run records, with no duplicate submission. Current user
  origins and data were not used for these tests.

These observations support reliable experiment handling. They do not show that
users need another editor or that the Web improves mathematical reasoning.

## Where the research experience breaks down

1. **Research metrics are not general result objects.** Expected cut, negativity,
   logical error and trajectory errors are visible only because the reviewer
   prints JSON. Jobs has no generic task-level metric comparison for these runs.
2. **A final circuit is not the whole scientific artifact.** A density matrix,
   error-model table and observable trajectory have different interpretation
   needs. Probability-only outputs show raw arrays with No counts distribution.
3. **Single-file collection keeps .fqx, not arbitrary research outputs.** Each
   successful script wrote report.json, but that file was not independently
   collected from its temporary directory. The report survives as log text;
   structured export required developer API assistance. Project-file workflows
   may provide another path, but were not exercised and are not credited here.
4. **Small continuity friction remains.** Replacing the default example source
   leaves its Python Bell pair name. A result opened while comparison is active
   can leave the previous comparison in front until Single result is selected.
   Completed status also described Finished without console output despite the
   recorded report. These merit future fixes; none was repaired during the trial.
5. **Environment readiness is domain-specific.** Python/SDK availability did not
   imply molecular-integral/FCI readiness. Missing PySCF was reported honestly.

## Product decision supported by this evidence

Prioritize one workflow: **change a circuit experiment, compare the scientific
objective and resource cost, retain the rejected candidate, and reproduce the
chosen version**. Quantum algorithm developers are the most plausible initial
trial group because the current SDK/artifact/circuit workflow already contributes
observable value there. This is a hypothesis for a later trial, not user demand.

Before expanding into five domain-specific dashboards, the two highest-leverage
improvements to evaluate are:

1. Retain a structured research result alongside the exact code, inputs, units,
   method assumptions and .fqx files; compare metrics without parsing prose.
2. Render that result according to its shape (scalar/table/series/matrix), so
   counts are one supported result type rather than the implied universal output.

These are recommendations only. This review added no product features, pages or
buttons. Chemistry and advanced error correction should not be advertised as
complete workflows on this evidence. Live-Agent scientific quality remains
untested because the model endpoint was disconnected and paid calls were zero.
