# Backend atomic-write replacement inputs

Issue #93 tracks the remaining current-source provenance review. This private batch replaces `apps/cli/src/backends/shared/atomic-file.ts` from its exported synchronous contract and five current backend call sites. The earlier imported implementation body was not used as a design input. This is not a strict clean-room or rights-clearance claim.

The behavior contract is a synchronous replacement of one private text document at `<dir>/<file>`. A caller sees either the previous complete file or the new complete file; a failed replacement throws and leaves no temporary sibling. The callers need their write to finish before returning from preference/channel updates. The replacement uses only Node's `crypto.randomUUID`, `fs` exclusive create/write/sync/rename/unlink, and `path` operations. It creates new directories with private permissions, writes through a randomly named private sibling, and renames over the target so a symbolic link is replaced rather than followed. Crash durability beyond syncing the new file, cross-process read-modify-write locking, and Windows retry of externally locked targets are outside this helper's contract.

`verify:backend-atomic-file` exercises immediate visibility, complete replacement, private modes on POSIX, cleanup after a failed rename, basename rejection, and symbolic-link replacement on POSIX. The existing Claude/Codex channel and preference regressions, full CLI preflight, staged packages, and clean installed acceptance still apply. The broader renderer, backend, other source, and private-history rights questions remain open.
