# Workspace path replacement inputs

Issue #93 tracks current-source provenance before public release. This private batch replaces `apps/cli/src/dsh-adapter/channel/paths.ts` as one workspace boundary, using its exported declaration contract, the current file-action and session-tree callers, `FileCandidate`/`FileSuggestionFs` types, and existing session-CWD and file-completion behavior checks. The imported implementation body was not used as a design input. Prior access to the repository prevents a strict clean-room claim; this change alone does not clear rights.

The module normalizes POSIX, drive, UNC and extended Windows paths for session scoping. Exact workspaces and their descendants can match, while HOME and filesystem/share roots match only exactly. Dot segments are resolved lexically without crossing a drive or share root. For `@` completion, path-shaped queries list the addressed directory and preserve the typed separator. Deep scans skip common generated/build trees, keep bounded work per directory so a generated sibling cannot crowd out source, ignore unsafe entry names and non-file entries, and stop on cancellation. The filesystem service and session log remain the authorities; this helper does not read file contents or own sessions.

`verify:workspace-paths` runs focused source checks plus the existing CWD and completion fixtures. Full CLI preflight, staged package, and fresh installed acceptance still apply. The broader imported renderer, prompt input, other channel/backend modules, and private Git history remain unresolved under #93/#86.
